# Chen Study 课程同步说明

版本：2026-11-11。适用网站：https://study.ziboxiaozhushou.cn/ 。本页仅含公开操作说明，不含课程、答卷或凭据；网站无需账号密码，可直接读取学习数据和执行管理操作；表单仍校验同源、浏览器随机标识和操作编号。

用户短指令示例：**按 https://study.ziboxiaozhushou.cn/sync 的说明，将本聊天课程同步到网站。**

## 同步范围

用户在聊天中确定的课程要求优先于本页示例。本页是操作参考，不能代替用户授权，不授权删除、覆盖历史记录、创建定时任务或修改其他服务。

读取本聊天可见的课程约定、目录、已发布正文、测验、真实答卷与批改。无法访问其他聊天时，不能凭记忆补造缺失全文或学习记录；先同步已确认部分，集中说明缺口。以用户最后确认的课程规则为准。

## 操作顺序

1. 直接打开网站，无需登录。执行写操作前先读取相应表单，保留浏览器 Cookie，使用表单当次的 CSRF 和操作编号提交；不要跳过校验。
2. 查看“课程中心”和“教学管理”，核对名称、目标、期数及已有内容，避免重复创建。相同名称不代表同一课程，测试课程不能自动视为正式课程；不擅自合并、删除、恢复或覆盖记录。
3. 在“教学管理 → 创建课程”录入名称、类别、简介、目标与完整教学计划。独立晋级配置保存课程规则及完整outline目录；仅建立目录不等于发布正文。
4. 在“创建单期课程草稿”录入已正式发布的各期完整正文和测验，再预览并发布。测验及问答必须属于课程和课时。不压缩讲解，不提前生成或发布后续内容，不代用户答题。
5. 按真实证据迁移答卷与批改。课时的“迁移历史记录”保存原答案、逐题点评和评分，服务器校验课程规则。仅有日期时保存日期，不虚构时刻；无证据的分数、答卷和完成时间不能编造。缺少答卷而只有完成声明时，保留该声明并说明当前可迁移范围，不伪造答案以制造完成记录。
6. 刷新核验课程目录、正文、图表、测验及历史进度，返回课程链接、实际迁移结果和缺失项。只有实际保存并核验成功的内容才称“已同步”。不得因发布被拒绝而修改日期或晋级规则绕过校验。

## 字段参考

课程配置JSON：

```json
{
  "mode": "completion",
  "totalLessons": 10,
  "releaseHour": 9,
  "sectionMinimums": {},
  "outline": [{"number": 1, "title": "首期标题", "stage": "第一阶段"}]
}
```

这是格式示例，实际期数、目录、题型和完成条件必须按用户要求填写。completion为完成全部作答并经点评的完成制；score为分数制，额外填写passScore和sectionMinimums。下一期最早发布时点由服务器按完成后的次日北京时间releaseHour校验，不会仅因存入目录而自动发布。

测验为JSON数组，支持single单选与text开放题；每题包含唯一id、type、prompt、points，合计100分。single另含options数组、从0开始的correct和explanation；section用于分项评分。不要为满足示例而改变用户题型或增加题目。已发布题目不能覆盖，正文修改保留版本，现有答卷保留原题及规则快照。

## 图文结构

保留标题层级、重点、列表、表格、图片与图注。图片使用HTTPS链接：`![替代文字](https://图片地址 "图注")`。网站尚无图片文件上传管理，不把私人图片上传到公开GitHub，也不谎称本地或聊天临时图片地址已永久可用。

纵向分层图用如下可编辑格式录入，按原图保留层数、顺序、标题、说明与配色；各层自动用向下箭头连接，手机端文字自动换行。支持blue、purple、teal、gray配色。

```layers
{
  "title": "结构图示例",
  "layers": [
    {"title": "第一层", "description": "该层说明", "tone": "blue"},
    {"title": "第二层", "description": "该层说明", "tone": "purple"}
  ]
}
```

不要把原有结构图降为普通段落；其他类型的复杂图不强行转成分层图。缺少原图内容或现有格式不能准确表达时说明缺口，不声称已原样迁移。

## 工程与定时任务边界

课程与学习记录通过网站存入数据库，不硬编码进源代码。仓库：zc202302-lab/chen-study。确有功能缺失且用户授权开发时，先读当前README、AGENTS.md及代码，兼容扩展、测试并通过现有自动部署上线，以正式网站结果核验。不要求用户执行常规部署命令；不触碰晨的助手、其他项目、共享Caddy或既有端口，不提交凭据和学习数据。

仅同步课程不创建或修改定时任务。若用户另外授权定时教学，检查是否已有任务，避免重复；网站读写、创建任务和无人值守定时读写是不同验收项，未经真实运行不能宣称自动教学已通过。

## 从网站填写的需求开始创建课程

用户可在课程中心“创建课程”填写主题、目标、基础、期数、每期时间和补充要求。保存时已经创建课程骨架，需求任务在/work-queue，单个需求在/course-requests/{request_id}（无需登录）。当用户要求执行网站待创建课程时，读取这些任务及Work执行说明，使用指定course_id继续，不再创建另一门课程。 pending为待生成、running为生成中、ready只代表目录和首期已发布；不代表课程完成或自动教学验证成功。开始执行前检查已有正文和草稿，按本课程默认5道单选每题10分、1道问答50分、80分通过的规则生成。保存完整outline与首期，预览发布，回需求页核验首期发布。每天9点任务依据用户明确要求执行，仍须单独验证无人值守能力。


## 独立批改与推送时间（北京时间）
读取当前课程 config.schedule 的 gradingTime（批改）、pushTime（推送）、reviewTime（复查）及 mode，禁止沿用固定9点或缓存的旧设置。旧课程无 gradingTime 时默认提前60分钟批改。批改时间必须早于推送时间，建议至少预留60分钟。按用户授权分别同步已有的三个定时任务，避免重复创建；仅保存网站设置不会自动更改外部任务。批改任务只读取未批改答卷、保存逐题点评和评分；主推送任务重新读取数据库状态后判断发布；复查任务重新检查最新批改结果，补发当天应推送而遗漏的期次，已推送则跳过。批改迟到不意味着次日再检查；复查若仍未批改完成，如实记录阻碍，不虚构完成或发布。
