## 现有项目保护

不得覆盖或删除/opt/chen-assistant、/opt/chen-cook、/opt/sms-relay、/opt/us-relay，不清理共享Docker资源，不重启整个sms-relay项目。Caddy变更只新增Study块，先备份、校验，再平滑加载，失败时恢复原内容并复核已有站点。

Caddyfile为单文件bind挂载：更新时必须考虑原子替换可能导致容器仍引用旧文件的问题；不能只凭宿主机文件内容宣布生效，需核对容器所见内容与运行结果。

GitHub不保存测验答案、问答或进度，不提交密码、私钥、令牌或.env。数据库备份必须包含恢复演练，服务器同盘副本不算异地备份。

## 阶段1测试程序（已编写，尚待服务器实测）

为缩短验证周期，本阶段使用Node.js原生HTTP与pg驱动，不展开Next.js正式平台。该程序不调用任何模型API。登录使用Secure、HttpOnly、SameSite会话Cookie（7天）；写操作校验Origin及CSRF，数据库事务内更新状态和操作日志。重复操作编号不会再次写入，已完成状态仍可记录后续运行以验证定时任务。当前没有重置按钮，避免误改历史；完整并发、持久化和定时验收需部署后执行。

独立核验：`bash scripts/verify-db.sh`。查看状态：`docker compose ps`；查看故障：`docker compose logs --tail=80 app db`。不要发送.env内容。备份目录包含既有Caddy配置，须保持私有，不提交GitHub。脚本不删除任何卷、不停止既有项目；健康检查、真实HTTPS访问及已有站点回归需根据实际返回值判定。

## v0.2 网站功能与部署

本版在已验证Node.js服务上实现完整学习流程，使用服务器渲染HTML、少量前端交互、Markdown与HTML清洗；保留PostgreSQL和Docker架构。暂不切换Next.js，以减少迁移、前端编译和服务器资源占用。课程数据及功能接口不依赖某个前端框架。

页面：学习首页、课程中心（搜索/分类）、独立课程目录、课时阅读与测验、逐题点评、课程问答及追问、学习档案、Work教学管理、课时预览及版本维护。课程目标中保存教学计划，阶段及期数独立配置；开放题和单选题可混合、数量自定，分值总计100。完成制与分数制分离，支持实战等分项最低分。答卷保存题目及规则快照；已发布题目不可更改，正文编辑保留历史版本。历史课程尚未导入，不编造已有课程正文、考试记录或完成日期。

管理创建顺序：课程 → 单期草稿 → 预览 → 发布。学习顺序：阅读 → 全部答题统一提交 → Work读取答卷并逐题点评 → 服务器更新进度 → 次日配置时点允许发布下一期。Work回答提问后存入数据库。正式晋级由服务器根据规则计算；同一09:00批改后立即发布会被拒绝。重复操作编号不会重复写入。

首次升级已部署的通信测试服务：

```bash
cd /opt/chen-study
git pull --ff-only
bash scripts/update.sh
bash scripts/install-backup.sh
bash scripts/install-auto-update.sh
```

update.sh先备份数据库，再执行兼容式数据库结构扩展，只更新Chen Study应用与数据库容器，不运行Caddy配置接入脚本。失败恢复旧程序，不自动删除或回滚数据库。所有迁移必须继续保持向后兼容。

自动部署采用GitHub Actions检查与镜像构建验证 → 服务器每5分钟只读检查最新main提交对应CI结果 → 通过后执行更新。现有网络条件下不需要GitHub向服务器SSH，也不需要额外服务；首次安装定时器及完整自动更新链路仍需实测。镜像构建验证在CI执行，服务器当前仍以轻量npm依赖安装构建镜像；并未声称服务器直接下载CI镜像。GitHub API限流、网络失败或CI未通过均停止部署并保留现有版本。

备份：每天北京时间03:30生成PostgreSQL自定义格式备份；轮转尚未自动删除任何备份，应定期检查容量。`scripts/restore-check.sh <备份文件>`在临时数据库恢复并核查后清理临时数据库，正式库不受影响。同盘备份不是异地备份，异地目标仍待确定；不能将这一项标为已完成。

日志及状态：`docker compose ps`、`docker compose logs --tail=80 app db`、`systemctl list-timers chen-study-*`、`journalctl -u chen-study-update.service -n 50 --no-pager`。升级失败应保留日志，禁止清理其他项目或共享Caddy证书。

本地验收使用PGlite（PostgreSQL引擎）验证SQL、学习全流程、重复提交、分项判分和隔日发布；生产连接并发锁、容器资源、HTTPS、手机布局、自动备份/更新、定时Work浏览器仍须生产实测。当前Work会话浏览器读写已于2026-11-03完成，服务器SQL独立确认work-test-001为completed、版本1；操作编号91b160d6-f618-4b55-9fb8-f14d0900b6c9。本版功能部署结果必须以实际运行输出为准。

## 历史课程迁移

课时发布后可从“迁移历史记录”导入原答卷和原批改，按该课时题目及课程规则计算成绩。仅有年月日时保存日期证据，不生成提交或完成时刻；迁移操作时间独立保留在执行记录中。已有答卷、完成记录或历史导入时拒绝覆盖。通过记录计入课程进度并按原学习日期的次日北京时间发布小时计算下一期资格；不会自动创建、解锁或发布后续正文。

课程晋级配置可包含outline列表，每项为number、title、stage；尚无正文的目录项只显示待发布，不创建占位测验。正式课时存在时按期数覆盖该显示项。
